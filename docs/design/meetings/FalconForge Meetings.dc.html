BRIEFMeetings & attendance — assumptions and system
What I assumed
  • Roster of ~21 students; grids show 10 rows then truncate in these mocks.
  • Check-in requires an authenticated session. Scanning while logged out routes through login, then completes the check-in.
  • Every occurrence has its own event ID (FF-0842). The QR and the typed code both encode that single occurrence and only work inside its check-in window, so a code saved from an earlier meeting is dead.
  • Check-in window defaults to 15 min before start until event end. Coaches can extend it.
  • States: Present / Excused / Absent. No late tracking — a scan inside the window is simply Present. Coaches can override any state.
  • Nobody is auto-marked absent — unrecorded students show as "—" until a coach saves the roster.
  • Recurring events prompt on save: this occurrence / this and future / whole series. A series shares its title and settings but never its ID — Monday build sessions run FF-0842, FF-0849, FF-0856…
  • Deadline-type events carry no attendance and no QR.

Open questions for you
  • You skipped the live check-in question, so I included a live scan feed with timestamps and a "close check-in" action. Say the word and I'll cut it.
  • Excused-absence requests from students are out of scope per your answer — the coach sets Excused manually.
  • Attendance % appears in the sidebar and on the summary screen, but not on student profiles.

Notes for implementation
Every occurrence is its own record with its own event ID and QR, generated when the series is created — a student cannot reuse last week's code. Editing one occurrence forks it from the series; editing the series leaves already-issued IDs alone. Changing the time re-derives the check-in window unless it was overridden.
